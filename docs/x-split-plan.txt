Author: pairing session, Aug 3 2026.  Drivers: memory project_x_native_style + own research.

WHY
---
LinkedIn grows (2600); X is stuck (~60) because the SAME LinkedIn-style post (long + polished
cards) is forced onto X. Small X accounts need NATIVE X style. Keep LinkedIn exactly as-is;
generate a SEPARATE short, native X version — and, where the content supports it, a short THREAD.

OUR RESEARCH (2026, independent of Groq) — validated + added:
  VALIDATED: short + strong hook; text-only (no cards); link in the REPLY not the body
    (link posts lose up to ~94% reach in 2026; Premium softens it — Lubo has Premium).
  ADDED (Groq missed): THREADS get 5-10x impressions (each tweet gets its own boost);
    X wants its OWN timing (build-in-public crowd active Tue-Thu ~9-11am ET) + cadence (1-3/day).
  THE HONEST BIG ONE (out of pipeline scope): the #1 growth lever is REPLYING to bigger
    accounts (70/30 rule; replies ~15x, conversations 50-150x a like) — MANUAL, ban-risky to
    automate. Better posts help but do NOT grow X alone. -> future "reply-draft assistant".
  VIDEO gets the most reach now, but is a separate production track (see project_video_ads).

DESIGN (locked)
---------------
- The X version is a NATIVE REWRITE of the already-written LinkedIn post: same facts, X style,
  returned as a LIST OF 1-4 TWEETS (1 = single post; 2-4 = a thread when the content supports it).
  One extra LLM call, grounded in the truthful LinkedIn text (no new claims). Mirrors
  writer.carousel_from_text (reshape existing -> new format).
- Stored on the post as x_thread (JSON list of tweet strings). Generated at GENERATION time so
  Lubo can review/EDIT before approving.
- Publish PER-PLATFORM: LinkedIn = post_text + cards (unchanged). X = the thread posted as a chain
  (tweet1 -> reply -> reply...), TEXT-ONLY (no images), then the tracked short link in a FINAL reply.
  If x_thread is missing, X falls back to a single post of post_text (safe).
- X-TIMING (Phase 5, optional): hold the X publish for the next good X window (Tue-Thu ~9-11am ET)
  instead of posting the instant Lubo approves. LinkedIn still posts immediately on approval.
- All in the publisher. No product app, no nginx, no new outward permission. One real post at the end.

PHASE 1 — X-native writer (returns a thread) (code + tests)
--------------------------------------------------------------------------------
1.1 writer.write_x_thread(topic_name, linkedin_text, hashtags=None) -> list[str] | None.
    system = build_system_prompt() + X_FORMAT override: the research/Groq rules + 3-4 few-shots
    per topic. Ask for 1 to 4 short tweets (hook first; thread ONLY if the content genuinely has
    2-4 distinct beats; else a single tweet). JSON out: {"tweets": ["...", "..."]}. Plain text,
    no cards, no "swipe", no markdown. Use ONLY facts already in the LinkedIn post.
1.2 Parser: return the tweet list; drop empties; strip markdown/"swipe"; soft length nudge
    (Premium allows >280, but keep each tweet tight). Cap the list at 4.
1.3 Tests: prompt carries the X rules + the LinkedIn text + few-shots; returns 1-4 tweets;
    single-tweet path; thread path; provider failure -> None (caller falls back).
ACCEPTANCE: write_x_thread returns a native 1-4 tweet list; tests green.

--------------------------------------------------------------------------------
PHASE 2 — Store + generate the X thread (code + tests)
--------------------------------------------------------------------------------
2.1 Model: PublisherPost.x_thread = Column(JSON, nullable=True)  # list of tweet strings.
    create_all picks it up (additive). Expose in api PostOut for the dashboard.
2.2 In Pipeline.generate_post (+ _finish_carousel): after post_text is finalized, call
    write_x_thread(topic, post_text, hashtags) and store x_thread. NON-FATAL: failure -> None.
    Inside the same Langfuse trace.
2.3 Tests: a generated post carries x_thread (mock the writer); failure -> None + post still saved.
ACCEPTANCE: pending posts carry post_text (LinkedIn) + x_thread (X, list of tweets).

--------------------------------------------------------------------------------
PHASE 3 — Publish per-platform: X thread, text-only, link in final reply (code + tests)
--------------------------------------------------------------------------------
3.1 _publish_to_platform / the publish loop become platform-aware:
      - LinkedIn: post_text + images — unchanged.
      - X: post x_thread as a chain — publish_text(tweet1) -> reply(prev, tweet_n) for the rest;
        NO images (text-only). Fall back to a single post of post_text if x_thread is empty.
3.2 After the thread, the tracked short link goes in a FINAL self-reply (_tracked_cta short link).
3.3 x_client may need a small helper to reply-chain (reply already exists; just chain on the
    returned ids). Non-fatal per tweet: a failed continuation never breaks the first tweet.
3.4 Tests: X posts N tweets as a chain (never publish_images); link reply is last; LinkedIn still
    sends images; x_thread empty -> single post fallback.
ACCEPTANCE: X publishes a native thread (or single), text-only, link last; LinkedIn unchanged.

--------------------------------------------------------------------------------
PHASE 4 — Dashboard: show + edit the X thread (code + tests)
--------------------------------------------------------------------------------
4.1 PostOut exposes x_thread. Dashboard renders an "X version" block (each tweet on its own line/
    card) under the LinkedIn text, so Lubo sees BOTH before approving.
4.2 Edit-before-approve for X: PATCH /api/posts/{id} accepts x_thread (list); dashboard "Edit X"
    lets Lubo tweak/split/merge tweets (a simple textarea per tweet, or one box split on blank lines).
4.3 Tests: PATCH updates x_thread (pending-only); dashboard shows the X block.
ACCEPTANCE: Lubo reviews + edits the X thread on the dashboard; ONE approval still publishes both.

--------------------------------------------------------------------------------
PHASE 5 — X-timing: publish X in the good window (OPTIONAL; can defer)  (code + tests)
--------------------------------------------------------------------------------
5.1 On approval: LinkedIn publishes immediately (as today). The X publish is QUEUED for the next
    X-optimal window (Tue-Thu ~9-11am ET, configurable) instead of the next 5-min loop.
5.2 Mechanism: a per-destination "publish_after" timestamp on PublisherDestination (or a small
    scheduled_x_at on the post); the publish loop only sends X once now >= publish_after.
5.3 Tests: X held until the window; LinkedIn immediate; a post approved inside the window goes now.
NOTE: this is the most complex piece (adds scheduling state). If we want v1 simple, SHIP 1-4 and
    do timing as a fast-follow. Recommend: build 1-4 first, decide on 5 after seeing it work.
ACCEPTANCE: X posts land in the high-traffic window without Lubo timing his approvals.

--------------------------------------------------------------------------------

RISKS / SAFETY
--------------
- Publish-path change (Phase 3) is the sharp edge: test that X never sends images + posts the
  chain in order; LinkedIn never loses its images. Fallback (x_thread None -> single post) keeps
  X safe if generation fails.
- Extra LLM call per post = pennies; non-fatal so it never blocks a post.
- Thread reply-chain: each continuation non-fatal (first tweet always stands).
- All publisher-only; container-testable; one real post only at the very end.
