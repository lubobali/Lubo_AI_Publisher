WHY
---
LinkedIn grows (2600), X is stuck (~60) because the SAME LinkedIn-style post (long +
polished cards) is forced onto X. Small X accounts need NATIVE X style. So: keep LinkedIn
exactly as-is; generate a SEPARATE short, punchy, TEXT-ONLY version for X.

THE X RULES (from Groq, Lubo agrees) — the writer's spec:
  short + direct + human; strong first-line HOOK; mostly <280 chars; 2-4 short lines;
  NO cards (text-only); no "swipe to see"; no LinkedIn storytelling; no soft openings.
  Per topic: building-in-public=one update/number; ai_news=one sharp take; tech_talk=one
  idea said simply; biohacker=stopped/started + result. Goal: stop the scroll in 1 second.
  The link stays in the X self-reply (already working: lubot.ai/go/<code>).

DESIGN (locked)
---------------
- X version is a NATIVE REWRITE of the already-written LinkedIn post (same facts, X style) —
  ONE extra LLM call, grounded in the truthful LinkedIn text (no new hallucination), applying
  the X rules + few-shots. (Mirrors writer.carousel_from_text: reshape existing -> new format.)
- Stored on the post as a new column x_post_text (nullable). Generated at GENERATION time so
  Lubo can review/EDIT it before approving.
- Publish is PER-PLATFORM: LinkedIn = post_text + cards (unchanged); X = x_post_text, TEXT-ONLY
  (no images) + the self-reply link. If x_post_text is missing, X falls back to post_text (safe).
- All in the publisher. No product app, no nginx, no new outward permission. One real post at the end.

PHASE 1 — X-native writer (code + tests)
--------------------------------------------------------------------------------
1.1 writer.write_x_post(topic_name, linkedin_text, hashtags=None) -> str | None.
    system = build_system_prompt() + X_FORMAT override (the X rules above + 3-4 few-shot examples
    per Groq). user = "Here is my LinkedIn post about <topic>. Rewrite it as a NATIVE X post:
    <rules>. Use ONLY facts already in it. Return plain text (no cards, no swipe)."
    Reuse the NIM->OpenRouter provider loop (share a helper with write_carousel if clean).
1.2 A light parser/guard: strip to plain text, drop any leaked "swipe"/markdown, soft length
    nudge (not a hard truncate — X premium allows longer; keep it short by prompt).
1.3 Tests: prompt carries the X rules + the linkedin text; output is short-ish; no "swipe";
    provider-failure -> None (caller falls back to post_text).
ACCEPTANCE: write_x_post returns a short native rewrite; tests green.

--------------------------------------------------------------------------------
PHASE 2 — Store + generate the X version (code + tests)
--------------------------------------------------------------------------------

2.3 Tests: a generated post has x_post_text populated (mock write_x_post); failure -> None + post
