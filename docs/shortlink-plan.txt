THE SAFETY-FIRST DESIGN (why this shape)
----------------------------------------
The shortener lives ENTIRELY in the PUBLISHER (the app we already own + deploy):
  - a tiny short_links table in the PUBLISHER DB (we control it)
  - the redirect route GET /go/{code} served by the PUBLISHER's FastAPI
  - short codes generated LOCALLY at publish time (a normal local DB write — no cross-system
    call, no new network failure mode)
The LuBot PRODUCT APP and its DB are NOT TOUCHED AT ALL. No product route, no product
migration (so the D-OPS-4b lockstep rule does not apply), no product deploy.
The ONLY shared-infra change is ONE nginx line: lubot.ai/go/ -> the publisher (127.0.0.1:8100).
Blast radius = the publisher + one nginx rule. Nothing else.

FLOW
----
click lubot.ai/go/a7x
  -> nginx routes /go/ to the publisher (:8100)
  -> publisher looks up "a7x" in short_links -> 302 to lubot.ai/?utm_source=...&utm_campaign=...
  -> browser lands on the real lubot.ai (LuBot frontend), which logs the UTM to user_events (as today)

PHASE 0 — DESIGN (locked)
--------------------------------------------------------------------------------
0.1 Code: 5-char base62 (~916M combos), URL-safe, no ambiguous chars if easy. Unique.
0.2 Idempotent: one code per (platform, campaign). Same topic+day+platform reuses its code
    (utm_campaign = topic-date already, so this is correct, not a bug). Re-publish = same code.
0.3 short_links row: code (unique), platform, campaign, dest_path (default "/"), created_at.
    dest = "/{dest_path}?utm_source={src}&utm_medium={med}&utm_campaign={campaign}".
0.4 Unknown code on click -> 302 to bare lubot.ai/ (graceful; never a dead 404 for a visitor).
0.5 Redirect target is RELATIVE ("/?utm_...") so host is inherited (works even if tested on
    publisher.lubot.ai directly). For the live link we force host lubot.ai in the emitted link,
    but the 302 Location stays relative -> lands on whatever host served it (lubot.ai in prod).
0.6 Body stays clean: publisher STOPS tagging the body. The one tracked link is the comment.

--------------------------------------------------------------------------------
PHASE 1 — Publisher shortener core (code + tests, deploy is safe/no behavior change)
--------------------------------------------------------------------------------
Work in /srv/lubot-publisher, feature branch.
1.1 Model: PublisherShortLink (code unique, platform, campaign, dest_path, created_at) in
    src/models.py. Auto-created by create_all (publisher pattern — no migration file needed).
1.2 src/shortlinks.py:
      - get_or_create_code(session, *, platform, campaign, dest_path="/") -> code
        (reuse existing (platform,campaign) row; else generate a unique 5-char code, insert)
      - resolve(session, code) -> dest string or None
      - _utm_dest(platform, campaign, dest_path) -> "/{path}?utm_source=..&utm_medium=..&utm_campaign=.."
        (platform li/tw/rd -> linkedin/twitter/reddit; medium li/tw->post, rd->comment)
1.3 Redirect route in src/api.py: GET /go/{code} -> resolve -> RedirectResponse(dest, 302);
    unknown -> 302 to "/" ... NO: to "https://lubot.ai/" bare (graceful). Cache-Control: no-store.
1.4 Tests (tests/unit + test_api): code gen unique+idempotent, resolve, /go/{code} 302 +
    Location has utm, unknown code -> graceful redirect, non-lubot never involved.
ACCEPTANCE: tests green. Deploying this is SAFE — it only ADDS a table + a /go endpoint;
    it does NOT change how posts are published yet. Nothing posts a short link.
ROLLBACK: drop the route + model usage; table is inert.

PHASE 3 — nginx: make lubot.ai/go/ reach the publisher (the ONE shared-infra touch)
--------------------------------------------------------------------------------
3.1 Add to the PROD lubot.ai vhost (/etc/nginx/sites-enabled/lubot):

3.2 nginx -t   (MUST pass — do NOT reload on error)  ->  systemctl reload nginx

- LinkedIn comment API real behavior only provable on a real post (4.5, Lubo-gated); non-fatal.
- Strict order: redirect live (Phase 3) BEFORE the publisher emits short links (Phase 4) = no dead links.
